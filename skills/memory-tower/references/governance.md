# PSRD 治理细则（governance）

## 1 治理四步（改内存层文件必经）

```
gate → 改 → ledger → seal → verify
```

| 步 | 命令 | 作用 |
|---|---|---|
| 快照 | `memgov.py gate <文件>` | 记 prev sha8，可追溯改前状态 |
| 改 | （正常编辑文件） | 就地改，别换文件名 |
| 记账 | `memgov.py ledger -m "动作" -l R` | 写 LEDGER.jsonl：时间/actor/文件/层级/动作/前后 sha8 |
| 封哈希 | `memgov.py seal` | 重算并写 INTEGRITY.json，锁定当前状态 |
| 验封 | `memgov.py verify` | 比对 sha，报告「无账改动」（改动没走 ledger）|

**铁律：改 INDEX/P/R/S 没有账 = 可疑改动**（`mem_lint.py` 会报 🔴）。

## 2 体积阈值 + 超限处理

| 层 | 帽 | 超限时 |
|---|---|---|
| I INDEX.md | 8K | 内容下沉，只留目录行 |
| P MEMORY.md | 10K（平台硬帽）| 尾巴被静默丢弃 → 必须下沉 R/S |
| R RULES.md | 20K | 已否决/过期条目移 `_archive/`，本体留指针 |
| S SECONDARY.md | 300K | 原样搬到 `_archive/SECONDARY_*.md`，本体留指针 + 目录行 |
| D YYYY-MM-DD.md | — | 只留最近 5 天，旧的删/归档 |

## 3 优先级（冲突裁决，高→低）

`memgov.py precedence <关键词>` 输出命中条目的裁决顺序。

1. **用户当场最新明示** —— 未落 P 则下轮失效
2. **真源文件 / 锁件** —— config / SKILL.md version / 台账
3. **层序** —— P > R > S > D > 归档
4. **时效** —— 新 > 旧（已被显式作废的旧值不得复活）
5. **机制 优于 结论** —— 防「结论对 + 论证错」
6. **具体 > 一般**

## 4 归档（不删除，只下沉）

- 原则：**原样搬迁**（零改动），本体留指针 + 目录行。
- 归档前三判据：①无活跃引用 ②不在 P 层口径 ③不是唯一真源。
- 落点：`_archive/SECONDARY_distilled_<日期>.md` 之类。

## 5 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `PSRD_MEM` | 当前目录下 `.psrd/` | 记忆目录 |
| `PSRD_ACTOR` | `agent` | 记账署名 |
| `PSRD_EXTERNAL` | `{}` | 外部真源路径（JSON 字符串）|
| `PSRD_WS` / `PSRD_CLAW` | 空（不检查） | mem_lint 旧环境残留检查 |

## 6 对外分发前必扫清单（2026-11-21 立）

**判据：命中数必须为 0。命中即阻断发布，不写「下版再改」。**

| 类别 | 会伤到什么 | 举例（描述，不写完整样态） |
|---|---|---|
| 路径 | 内部目录结构、本机用户名 | 本机绝对路径、家目录、"用户"目录、Windows 盘符路径 |
| 人名 / 角色 | 暴露团队与内部称呼 | 项目内部约定的成员称呼 |
| 平台 ID | 外流后可被定位或冒用 | 飞书 open_id / chat_id / app_id 一类的 `xx_` 前缀长串 |
| 凭证 | 最严重，见即阻断 | 模型 key、Bearer 头、环境变量文件（dotenv）内容、password / secret 赋值 |
| 内部目录名 | **往往同时是功能 bug** | 只有本机存在的顶层目录（外部用户没有这层，某层永远解析为空） |
| 数据标识 | 泄露业务范围 | 自有库名、业务代号、客户名 |

**扫描方式（唯一入口，别手打正则）**

```bash
python3 scripts/pub_scan.py <解包目录>          # 退出码 0=干净 / 1=命中 / 3=目录不存在
python3 scripts/pub_scan.py <解包目录> --list   # 只列位置，不打印原文（贴日志用）
```

模式写在 `scripts/pub_scan.py` 里，**用字符串拼接构造**：本文件也在包内，若把正则以完整字面量写进来，扫描器会扫到自己那几行，变成永远红的假闸门。同理，本表只描述不写样态。

**三条配套纪律**

1. **扫解包产物，不扫源目录**：源目录的 `.bak_*`、测试数据会稀释结果；包才是别人拿到手的东西。
2. **模式按「会伤到谁」列全，不按「想到几个」列**：上表六类一起扫。真实教训——只扫前三类时漏掉「内部目录名」，而那处不只是泄露，是让外部用户某一层记忆永远为空的功能缺陷。
3. **命中要分类处理**：兼容性回退（新路径优先、旧路径仅 fallback 且有注释）可接受；**外部用户必然为空 ⇒ 按 bug 修，不按文案改**。
