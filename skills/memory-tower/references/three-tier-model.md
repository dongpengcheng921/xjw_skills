# PSRD 三层加载模型（three-tier-model）

## 核心思想

AI 的记忆问题不是「记不下」，而是「每轮都全量塞进上下文会爆」。

PSRD 的解：**按「每轮是否需要在场」分层**。常驻注入的只有 I+P 两层（≤18K 字符），
其余 R/S/D 全部按需读。于是体系可以持续增长（新规则进 R、新细节进 S、新流水进 D），
内存占用保持不变。

## 五层职责

| 层 | 文件 | 一句话职责 | 读法 | 写法 |
|---|---|---|---|---|
| I | INDEX.md | 目录 + 关键词 + 指针 | 每轮都在 | 只加目录行，禁搬内容 |
| P | MEMORY.md | 每轮都要知道的口径 | 每轮都在（≤10K）| 精炼，超了下沉 |
| R | RULES.md | 纪律 / 规则 / 判据 | Grep → Read 命中行 | 追加 §N，判据写清 |
| S | SECONDARY.md | 技术细节 / 数据源 / 蒸馏 | Grep → Read 命中行 | 追加 + 更新目录行 |
| D | YYYY-MM-DD.md | 当天流水 | 按日期 Read | 新建，留 5 天 |

## 判据：这条内容放哪层？

- 「**每轮对话都必须知道**，否则会犯错」→ P（身份、红线、报数口径、当前结构）
- 「**做某类事时要遵守的规矩**」→ R（可 Grep 的判据）
- 「**某个技术细节/数据源/脚本路径，用到才查**」→ S
- 「**今天干了什么**」→ D
- 「**索引/速查**」→ I

## 为什么不是「一个文件记所有」

一个文件记所有 = 每轮全量注入 → 要么爆上下文，要么精简到丢信息。
分层后：P 只管「当前口径」（小、准），R/S 只管「历史积累」（大、按需）。
这是「内存占用 O(1)、知识积累 O(n)」的关键。

## 与「自动蒸馏」的区别

- 自动蒸馏（如 memory-to-skill）：等「反复出现」才提炼 → 慢、被动。
- PSRD：**第一次就写死进 R/S** → 快、主动。
- 结论：规则型团队用 PSRD，不用等蒸馏。
